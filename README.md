# ラクマート発注レシピ v4

## 今回の変更
- **構成品の区分**：本体／付属品。入庫一括は、入庫数をどの便に数えるかを本体の行だけで決めます。
- **同じ回に共有するとき**：分ける（初期値・商品ごとに別注文）／まとめる（1行にまとめ、使う全商品の備考を入れる）。
- **明細の倍数・最低数量**：数量は「発注予定数 × 数量倍率」を整数に切り上げ → 最低数量まで引き上げ → 倍数に切り上げ。
- **数量倍率＝入庫一括の入数**：発注記録（`rakumart_order_records`）経由で、入庫一括の原価按分に使います。
- **備考テンプレート**：`{構成品名}`（注文詳細の番号。複数行はカンマ区切り）、`{構成品名:規格値}`（その1行の番号）、`{数量}`（オーダー数）。末尾の `●商品コード▲日付-数量` は自動で付くので書きません。編集画面に差し込みボタンと試し表示があります。
- **たたき台の改善**：サイズ・カラーの半角カンマ区切りを別々の明細に分け、末尾の `(3)` を数量倍率として読みます（例：`浅灰,深灰,黑色` → 3明細、`20*30(3)` → 倍率3）。全角「，」や「/」は1つの規格名として扱います。本体の構成品名は「本体」、ほかは「付属品1, 2…」になります（差し込み名になるので短くしています）。
- **発注記録**：Playwright が注文詳細で番号が振られた行ごとに保存します（注文NO・No・商品コード・倍率・単価）。単価は `rakumart_price_history` ビューで推移を見られます。

## 適用
1. Supabase SQL Editor で `supabase/rakumart_order_recipe_v4.sql` を実行（何度実行しても大丈夫です）。
   - 新規環境は `rakumart_order_recipes.sql` → `rakumart_order_recipe_v4.sql` の順。
   - v4 より前に保存したレシピは、初回の実行時に「1番目の構成品＝本体、2番目以降＝付属品」に設定されます。セット品（ヨガ0setのソックスなど）は編集画面で区分を直してください。
   - **v4 適用後に `rakumart_order_recipe_reload_fix.sql`（下の v3 の手順）は実行しないでください。** 読込関数が v3 に戻ります。間違えて実行したら v4 のSQLをもう一度実行してください。
2. `src/App.tsx`・`src/App.css`・`src/lib/rakumartRemark.ts` を差し替えてビルド・デプロイ。
3. 入庫一括も同時に更新してください（発注記録を読むようになります）。

# ラクマート発注レシピ v3（前版）

## 今回の変更
- 発注レシピは「オーダー用」表示にだけ表示（前版仕様を維持）。
- レシピ未登録商品は、既存の `発注URL1〜3 / サイズ / カラー` から初回たたき台を生成。
- 発注URLが1件：自動で「構成品1件」としてたたき台を生成（未保存）。
- 発注URLが2件以上：「全部発注する / 代替仕入先 / 手動で作る」を選んでたたき台を生成。
- たたき台は自動保存しない。内容確認後に「保存」で初めてDBへ保存。
- 規格軸は任意。規格値だけで保存可能。
- UIは「規格値」を先、「規格軸（任意）」を後に変更。
- Playwright想定：まず規格値で探索し、同値候補が複数ある場合だけ規格軸を補助キーとして使用する前提。
- 保存後再読込RPC修正を維持。

## 適用
1. 前回の再読込修正SQLをまだ実行していない場合は、Supabase SQL Editorで `supabase/rakumart_order_recipe_reload_fix.sql` を実行してください。実行済みならDB変更は不要です。
2. `src/App.tsx` と `src/App.css` を差し替え。
3. ビルド・デプロイ。

`supabase/rakumart_order_recipes.sql` は新規環境用の全体SQLとして同梱しています。既存環境では今回新しいテーブル変更はありません。

## 初回作成例
- URL1だけ: 商品本体 + URL1 + サイズ/カラーを「規格値」として候補化。
- URL1/URL2が本体+袋: 「全部発注する」を選択 → 2構成品に分離。
- URL1/URL3が同商品の別ショップ: 「代替仕入先」を選択 → 1構成品の仕入先候補としてまとめる。

## 配送-階-特記

NE受注明細の商品名補完用に `products.shipping_floor` を追加しています。画面表示名は **配送-階-特記** です。

値は半角/全角スペースを含む空白で区切って複数指定できます。例: `PKT2-2F RPR`。NE受注明細では各要素を個別に判定し、不足している要素だけを追記します。

初回のみ Supabase SQL Editor で `supabase/product_shipping_floor.sql` を実行してください。

例:
- `PKT2-3F`
- `NP-2F`
- `TAK-3F`

TimerRunner / ne-sync-worker 側では空白区切りの各要素を個別に確認し、不足分だけ ` | 【PKT2-3F】 【RPR】` のように追記します。

## CSV更新のみモード

「一括追加/更新」画面に **更新のみ（商品追加しない）** を追加しています。

- ON: 商品DBに既に存在する商品コードだけを更新します。
- CSV内の未登録商品コードは追加せずスキップします。
- 画面下部に「更新予定」「未登録スキップ」の件数を表示します。
- 対象列に選んでいない列は更新しません。

`配送-階-特記` だけをCSVで一括更新したい場合は、対象列を `配送-階-特記` のみにして、このモードをONにしてください。
